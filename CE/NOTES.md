# PopSNES 技術メモ(SHARP Brain / Windows CE)

コードは AI(Claude)が書きました。製作者はプログラムを読めません。製作者がしたのは、AI への指示と、実機(PW-G5300)での確認です。

PopSNES を作る中でわかったことのうち、実機で確かめたことと、このリポジトリのコードで裏付けが取れることだけをまとめています。Brain 向けにほかのエミュレータを移植するとき、作業を始める前に AI に読ませることを想定しています。

実機で確かめた機種は SHARP Brain PW-G5300 だけです。ほかの機種での動作は確かめていません。

各項目の最後の( )は、もとにした開発メモの記録です。開発メモでは、作業の区切りを「ラウンド」と呼んでいます。開発メモはリポジトリに入れていません。

v1.0.0 より前の直しは、コミット 3865d91(コアの直し)と 071eb01(フロントエンド)にまとめて入っています。

## 全体の作り

- PopSNES は libretro のフロントエンドとして作っています。`libretro/libretro.c` をそのままコンパイルし、`CE/ce_main.c` が `retro_init()`・`retro_load_game()`・`retro_run()` を呼び、画面・音・入力・環境のコールバック(`retro_set_*` に渡すもの)を実装しています(開発メモの「アーキテクチャ」)
- コアで変えたファイルは [`LICENSING.md`](LICENSING.md) の2節にまとめています
- `AppMain.exe` が使う DLL は `COREDLL.dll` だけです。`arm-mingw32ce-objdump -p AppMain.exe` で確かめられます(開発メモの「v1.0.3 の1回目」、2026-10-08)
- `aygshell.dll` は使っていません。使わない形に変えたあと、実機で動くことを確かめました(開発メモのラウンド15、2026-08-03)

## ビルド

- `CE/Makefile` は `-march=armv5te -mno-unaligned-access` を付けています。cegcc の既定のターゲット(ARMv4T)では、コアの ARM アセンブリが使うレジスタ指定の `blx` がアセンブルできませんでした(開発メモの「ビルド環境のハマりどころ」)
- `-flto` は使っていません。この cegcc の `ld` が LTO のプラグインのオブジェクトを扱えないためです(開発メモの「ビルド環境のハマりどころ」)
- cegcc の `errno.h` と `direct.h` は、`#include_next` の先が見つからずにエラーになります。中身の無い `CE/compat/errno.h`・`CE/compat/direct.h` を `-Icompat` で先に読ませて避けています。どちらのヘッダの中身も、このコードでは使っていません(開発メモの「ビルド環境のハマりどころ」)
- `src/os9x_65c816*.S` の `.include` は、ファイル名を小文字の `.s` で書いていました。ファイル名の大文字と小文字を区別するファイルシステム(WSL の ext4)ではアセンブルできなかったので、`.include` の文字列を実際のファイル名(`.S`)に合わせました(開発メモのラウンド17、2026-08-07)

## 画面

- GAPI(`gx.dll`)は使っていません。描画は GDI だけでしています(開発メモのラウンド26、2026-08-28)
- 画面の大きさは 480×320 でした(実機のログ)。今のコードは `ce_display.c` の `CeDisplayInit()` で `GetSystemMetrics(SM_CXSCREEN / SM_CYSCREEN)` から取っています(開発メモの「ビルド環境のハマりどころ」)
- 画面と同じ大きさの RGB565 の DIB セクション(`CreateDIBSection`、`BI_BITFIELDS`、`biHeight` を負にして上から下の順)にアプリのコードで拡大して書き、`BitBlt` で等倍のまま画面へ送ります(`ce_display.c` の `CeDisplayBlitRGB565()`)(開発メモのラウンド26、2026-08-28)
- 表示の大きさは比率を決めてあります。x1 は等倍、x1.5 は 3/2(256→384)、Wide は 7/4(256→448)、Full は 15/8(256→480)です。どれも2画素を32ビットで1回に書きます。Full は 8画素→15画素を1回分にすると30バイトで4の倍数にならず、次の書き込みの番地がそろわなくなるので、16画素→30画素(60バイト)を1回分にしています(`ce_display.c` の `s_scale15over8`)(開発メモのラウンド26、2026-08-28)
- 同じ ROM(256×224)で、表示の大きさごとに実機のログ(`perf: blit`)で転送の時間を測りました。どれも、前に使っていた GAPI の版より短くなりました(開発メモのラウンド26、2026-08-28)

| 表示 | GDI(平均 / 最大) | 前の GAPI の版(平均 / 最大) |
|---|---|---|
| x1 | 3ms / 4〜5ms | 7ms / 8ms |
| x1.5 | 5ms / 6〜7ms | 8〜9ms / 10〜11ms |
| Wide | 6ms / 7〜9ms | 9ms / 10〜11ms |
| Full | 7ms / 8〜11ms | 10ms / 11〜12ms |

- Full は、比率を決めずに1画素ずつ位置を計算していたときは平均 16ms でした。16画素→30画素の形にしたら 7ms になりました(実機のログ)。表示がおかしくないことも実機で確かめました(開発メモのラウンド26、2026-08-28)
- 4バイトにそろっていない番地に32ビットで書くと、Datatype Misalignment の例外で落ちました(BER の記録)。GAPI を使っていたころ、表示の横の位置が奇数の画素になる表示で起きました(開発メモのラウンド13、2026-08-03)
- GDI でウィンドウに直接描くので、ダイアログを閉じて見えた部分は描き直す必要があります。`ce_main.c` の `WndProc` の `WM_PAINT` で、ゲームを読んでいれば `CeDisplayForceRepaint()` を呼びます(開発メモのラウンド26、2026-08-28)
- メニューや設定画面の文字は、`AppMain.exe` に入れたビットマップフォントを `SetPixel` で描いています(`ce_bmpfont.c`)。フォントのファイルは要りません(開発メモのラウンド24、2026-08-27)。日本語の表示を実機で確かめました(開発メモのラウンド25、2026-08-28)

## 速さ

- GAPI を使っていたころの実機のログ(フレームスキップ 0)では、1フレームのうち、コアの音の合成(`S9xMixSamples`)は平均 0〜2ms、`retro_run` 全体は軽い ROM で 15〜16ms、重い ROM で 34〜36ms、画面の転送は 10〜12ms でした(開発メモのラウンド12、2026-08-02〜2026-08-03)。音の合成を測るコードは、そのあと消しました(開発メモのラウンド16、2026-08-03)
- 重いゲームで、表示を x1 に、透過エフェクトを OFF にして試したところ、体感では「多少よくなる程度」でした。時間は測っていません(開発メモのラウンド16、2026-08-03)
- ゲームごとのスピードハック(`ce_speedhack.c` の `CeSpeedHackApply()`)を入れました。スピードハックを当てるゲームの1本で、ROM の書き換えがログに出ることを確かめました。ただ、`retro_run` の時間の差は約1ms で、測るたびのぶれと同じくらいでした。体感ではよくなりましたが、数字では差が見えませんでした(開発メモのラウンド34、2026-09-25)
  - SA-1 を使うゲームには当てません。コアの SA-1 用の命令の表では、ハックに使う命令(Op42)の中身が `#ifndef SA1_OPCODES` で外れているためです(`ce_speedhack.c` のコメント)(開発メモのラウンド34、2026-09-25)
- フレームスキップ(Video Config の 0〜30)は、コアの `snes9x2002_frameskip` の `auto` を使います。コアは、音のバッファが足りなくなりそうなときにフレームを飛ばします。続けて飛ばす数の上限はコアでは 30 で決まっているので、設定した数に達したら、音のバッファの状態を「動いていない」と答えて、そのフレームを描かせます(`ce_video.c` の `CeVideoFrameSkipShouldForceRender()`)。重い場面で間引かれて体感がよくなること、軽い場面で余計にカクつかないことを実機で確かめました(開発メモのラウンド10とラウンド11、どちらも 2026-08-02)
- フレームの速さを合わせる処理が無かったころは、軽い ROM や PAL の ROM が実際より速く動き、音のリングバッファがあふれました(ログの `ring overrun`)(開発メモのラウンド37、2026-09-28)
  - `GetTickCount()` で時間を合わせたら、ログの fps は目標どおり(PAL で 50.0〜50.5)でしたが、`ring overrun` は出続けました(開発メモのラウンド37、2026-09-28)
  - 今のコードは、waveOut が開けているときは、`retro_run` のあと、リングにたまった音が目標の量(`ce_audio.c` の `CeAudioGetPacingTargetMs()`)以下になるまで `Sleep(1)` で待ちます(最大120回)。開けていないときだけ `GetTickCount()` で合わせます(`ce_main.c` の `WinMain`)。Sound Config のバッファ 16 KB で、`ring overrun` は出なくなり、音が途切れたのは起動したときの1回だけでした(実機のログ)(開発メモのラウンド37、2026-09-28)
  - バッファを 4 KB 未満(2048 フレーム。44kHz で約46ms)にしていたときは、目標の量が小さくなりすぎて、ほぼずっとフレームを飛ばす状態になり、描画は約5フレームに1回でした。PAL ではあふれ続けました(実機のログ)。この大きさは選べなくしました(開発メモのラウンド37、2026-09-28)
- BRR の展開をアセンブリから C(`src/soundux.c` の `DecodeBlockDSP()`)に替えたあとも、`retro_run` は 16〜18ms で変わりませんでした(実機のログ)(開発メモのラウンド38、2026-09-28)

## 音

- waveOut は1チャンネル(`nChannels = 1`)で開き、コアの左右の音を平均して1つにしています(`ce_audio.c`)。実機の音はモノラルでした(開発メモの「現在の状態」、2026-08-01)
- waveOut を閉じる前に `waveOutReset()` を呼んでいたときは、設定を変えて開き直すたびに「ポツッ」と鳴りました。`waveOutReset()` をやめ、送ったバッファが `WHDR_DONE` になるのを待ってから閉じる形(`ce_audio.c` の `CeAudioStop()`)にしたら、鳴らなくなりました(開発メモのラウンド14、2026-08-03)
- ビット数(16 / 8)を、設定画面で値を変えた時点で切り替えていたときは、OK を押すまで「ブー」と鳴り続けました。音を出すスレッドが新しいビット数で書き、waveOut は古いビット数のまま開いていたためです。値は `s_pendingBitDepth` に置いておき、OK のときに音を止めてから切り替え、開き直す形にしたら鳴らなくなりました(開発メモのラウンド14、2026-08-03)
- 音のリングバッファの大きさは、Sound Config で 8 / 16 / 32 / 64 / 128 KB から選べます(中はフレーム数で、4096〜65536)。以前は約256ms 分に決めてあり、音の遅れを体感しました。約128ms 分にしたら、体感で遅れが減りました(開発メモのラウンド27、2026-08-28、ラウンド30、2026-08-28、ラウンド37、2026-09-28)
- あるゲームの雷の音がおかしかったので、PC のエミュレータで録った音と実機で録った音を比べました。雷の前半は、PC では周期の無いノイズでしたが、PopSNES では途中から約346Hz の繰り返しの音(自己相関 0.96)になっていました。後半は、PC より約6倍高い音になっていました(開発メモのラウンド38、2026-09-28)
  - ノイズを、全チャンネルで共通の LFSR から、DSP のノイズの周波数(FLG)で作る形にしました(`src/soundux.c` の `GenerateNoise()`)。後半の低い音が PC と同じになりました(実機)(開発メモのラウンド38、2026-09-28)
  - BRR の展開を、計算の途中で16ビットに頭打ちにしてから2倍する形にしました(`src/soundux.c` の `DecodeBlockDSP()`)。前半の繰り返しの音が消えました(録音で自己相関 0.9 → 0.2〜0.4)。別のゲームの杖で打つ音も正常になりました。ほかのゲームの音に異常は出ませんでした(実機)(開発メモのラウンド38、2026-09-28)
  - ループするときに SRCN(音色の番号)を読み直す直しも入れましたが、調べた記録(DSP の書き込みのログ)では、雷のあいだ SRCN は KON の直前にしか変わっておらず、この症状とは関係しませんでした(開発メモのラウンド38、2026-09-28)

## 入力

- Brain の「決定」ボタンは `VK_RETURN` でした。ほかのボタンは、「音声」が 0xDC、「機能」が 0x14、「前」が 0x21、「後」が 0x22 でした(`ce_input.c` の名前の表)(開発メモの「現在の状態」、2026-08-01)
- ダイアログのボタンにフォーカスがあるとき、決定(Enter)は `IsDialogMessage()` が `BN_CLICKED` に変えてしまい、`WM_KEYDOWN` としては届きませんでした。そのため、キーの割り当てで決定ボタンを登録できませんでした(開発メモの「現在の状態」、2026-08-01)。今は、割り当てのボタンをサブクラスにして、`WM_GETDLGCODE` で `DLGC_WANTARROWS | DLGC_WANTALLKEYS` を返し、キーをアプリのコードで受けています(`ce_input.c` の `InputBtnCtrlProc`)(開発メモのラウンド22、2026-08-08)
- キーを割り当てるとき、`WM_KEYUP` も受けていたら、割り当てを始めるときに押した決定ボタンを離したことが新しいキーとして登録されてしまい、割り当てを待つ表示(今のコードでは「Press key」)がすぐ消えました。`WM_KEYDOWN` だけを受ける形にしたら直りました(開発メモのラウンド22、2026-08-08)
- 斜め(右上など)の行は、1つのキーで2方向を押します。`CeInputPoll()` で全部の行をいったん0にしてから OR でまとめます。行ごとに代入すると、同じ方向を持つ行どうしで打ち消し合うためです。斜めの入力が効くことを実機で確かめました(開発メモのラウンド23、2026-08-17)

## ダイアログ

- cegcc の `libcoredll.a` には `SetMenu` と `GetMenu` がありません(`CreateMenu`・`AppendMenuW`・`DrawMenuBar` はあります)。メニューは、`DialogBoxW` のダイアログにボタンを並べて作っています(開発メモの「ビルド環境のハマりどころ」)
- `HHTaskBar` のウィンドウを直接隠しても、タスクバーは消えませんでした。ダイアログは、タスクバーがいつも出ている前提で配置しています(開発メモのラウンド15、2026-08-03)
- RC の座標はダイアログ単位(DLU)で、画素ではありません。メインメニューは、ステートセーブとステートロードのボタンを足したとき、Exit が画面からはみ出しました(開発メモの「ビルド環境のハマりどころ」、2026-08-01)。Input Config は、8行×2列にして 190×200 DLU にしたとき、画面から見切れて OK ボタンが出ませんでした(開発メモのラウンド23、2026-08-17)。今の `ce_res.rc` では、メインメニューは幅 210・高さ 154、Input Config は幅 190・高さ 170 です
- 標準のボタンは、押し続けても繰り返しになりません。Video Config のフレームスキップの -/+ は、ボタンをサブクラスにして、押してから 500ms 後、そのあと 120ms ごとに値を変えています。押し続けて値が進むことを実機で確かめました(開発メモのラウンド13、2026-08-03)
- メインメニューのマスコットの絵は、背景の色を合成した 24 ビットの BMP にしています。cegcc の `libcoredll.a` に `TransparentBlt` が無いためです(開発メモのラウンド36、2026-09-25)
- リストボックスで A〜Z のボタンを押すと、選択が動きました。`ce_fileopen.c` の `FileListCtrlProc` で、空白以上の `WM_CHAR` を元のリストボックスに渡さずに捨てています(開発メモの「v1.0.2 の2回目」、2026-10-07、コミット 13551df、タグ v1.0.2)
- アイコン(.ico)には AND マスクを入れます。Pillow で書いた .ico にはマスクが無かったので足し、実機でアイコンを確かめました(開発メモの「v1.0.1 の準備」、2026-10-02、コミット 235ea06、タグ v1.0.1)

## ファイルと設定

- 設定をレジストリに書いていたときは、アプリを起動し直しても残りましたが、電源を切ると消えました。`RegFlushKey()` は `ERROR_NOT_SUPPORTED` を返しました(開発メモのラウンド8、ラウンド9(2026-08-01))。設定は `AppMain.exe` と同じフォルダの `popsnes.cfg` に書く形にして(`ce_config.c`)、電源を切っても残ることを実機で確かめました(開発メモのラウンド10、2026-08-02)
- 電源を切るときは、アプリの終わりの処理を通りません。カートリッジのセーブ(`.srm`)は、メニューを開いたときと、ゲーム中は30秒ごとにも書いています(`ce_main.c`)。ゲーム内でセーブしてから電源を切り、入れ直してもセーブが残っていることを実機で確かめました(開発メモのラウンド10、2026-08-02)
  - 30秒ごとと終わりのときは、中身が読み込んだとき、または前に書いたときと同じなら書きません(`ce_main.c` の `CeSaveSramIfChanged()`)。実機のログで、中身が変わらないあいだは書かないことを確かめました(開発メモの「v1.0.3 の1回目」、2026-10-08、コミット 1f2b887、タグ v1.0.3)
  - コアは SRAM の領域(0x20000 バイト)を確保するだけで、ROM を切り替えても 0 で埋めません。`.srm` が無いゲームでは、`CeLoadSram()` で 0x20000 バイトを 0 で埋めています。ROM を切り替えたあとの動作は確かめていません(開発メモの「v1.0.3 の1回目」、2026-10-08、コミット 1f2b887、タグ v1.0.3)
- ROM は `_wfopen()` で開いて、まるごとメモリに読んでからコアに渡します。コア(`src/`・`libretro/`)には `fopen()` の呼び出しが無く、`retro_load_game()` は `game->path` を使いません(開発メモのラウンド32、2026-09-05)
  - 日本語を含むフォルダからの読み込みと、日本語を含む ROM のファイル名での読み込みを、実機で確かめました

## 終わり方

- 終了は `ce_main.c` の `CeShutdown()` から `ExitProcess()` を直接呼びます。セーブの書き込みは `ExitProcess()` の前にしています(開発メモの「UI の流れ」)。メニューを通らずにアプリが閉じたときの動作は確かめていません(開発メモの「v1.0.3 の1回目」、2026-10-08)

## コアで直したこと

- S-DD1 を使うゲームで、起動したときのロゴがノイズになりました。S-DD1 の DMA は `Settings.SDD1Pack` が FALSE だと `S9xLoadSDD1Data()` で用意する表を引きますが、`libretro.c` では、この関数は何もしない形になっています。`snes_init()` で `Settings.SDD1Pack = TRUE` にして、`SDD1_decompress()` で展開する経路を通すようにしたら、ロゴが正しく出ました(実機)(開発メモのラウンド16、2026-08-03)
- lunoka 氏のゲーム『Mai Nurse』が、起動した直後に Datatype Misalignment の例外で落ちました。BER の PC の値を、strip する前の exe で `nm` で引くと、SPC700 の `TCALL 0` の処理(`src/spc700a.S`)の `ldrh` でした。`src/apu.h` の `SAPU` の `ExtraRAM` は奇数のオフセット(0x8B)にあり、TCALL / BRK はそこから2バイトを `ldrh` で読んでいました。`ldrb` を2回にしたら、起動するようになりました(開発メモのラウンド37、2026-09-28)

## デバッグの進め方

- アプリが例外で落ちたときは、[Brain Exception Reporter(BER)](https://github.com/Sgch/ber) で例外とレジスタを記録しました(開発メモのラウンド13、2026-08-03、ラウンド37、2026-09-28)
- デバッグログ(Video Config の「デバッグログを有効にする」)は既定で OFF です。`WinMain` で設定を読んでから有効にするので、それより前の行はログに出ません(`ce_main.c`)(開発メモのラウンド28、2026-08-28)
- ログを ON にすると、`perf: retro_run avg=… max=…` の行が出ます。速さの話は、この行の数字で確かめました(開発メモのラウンド12、2026-08-02〜2026-08-03、ラウンド26、2026-08-28)
- `CeLog()` は1行ごとにファイルを開いて閉じます。音の処理の中からほぼ毎フレーム `CeLog()` を呼んだら、ほぼ止まりました(ログの fps が 0.1)。調べるための記録は RAM のバッファにためて、メニューを開いたときにまとめて書く形にしました。調べ終わったあと、このコードは消しました(開発メモのラウンド38、2026-09-28)
